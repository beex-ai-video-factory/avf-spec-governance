**TITLE:** OpenTelemetry Distributed Context Propagation and Immutable Take Lineage Provenance Ledger  
**STATUS:** PROPOSED (C03 Solution Design Complete)  

---

## 1. Problem Statement
Cross-service request traces cannot be correlated across asynchronous message queues and browser workers. Take lineage lacks immutable end-to-end provenance graph linking assets, prompts, seeds, costs, and QC results.

---

## 2. Current Specification Baseline (v0.9.0)
The v0.9.0 specification lacks formal schema definitions, explicit state boundaries, and robust error/concurrency semantics for this domain.

---

## 3. Proposed Specification Changes (Option A vs Option B)

### OPTION_A: Strongest Practical Solution (Recommended)
OpenTelemetry standard trace propagation + PostgreSQL JSONB lineage graph in R02 with Prometheus metrics export in R14.

**Exact Architectural Changes:**
Adopt W3C Trace Context (traceparent, tracestate) across all HTTP, gRPC, and RabbitMQ/Redis event envelopes. Mandate TakeProvenance entity in R02 recording: project_id, scene_id, shot_id, prompt_version_id, model_id, seed, provider_params_hash, provider_job_id, cost_usd, raw_media_hash, qc_result_id, completed_at.

### OPTION_B: Credible Alternative / Trade-off Analysis
Custom text logging with grep-based log correlation.
