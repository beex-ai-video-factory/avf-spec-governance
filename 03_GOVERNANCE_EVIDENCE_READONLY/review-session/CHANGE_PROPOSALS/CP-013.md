# Change Proposal: CP-013 — Operator Console Human-in-the-Loop (HITL) Workflow Intervention and Manual Override State Machine

**CHANGE_ID:** CP-013  
**SOURCE_FINDINGS:** F-R06-002, F-R13-001, F-R13-002, F-R13-003, F-R13-004, F-R13-005, F-R13-006, F-R13-007  
**TITLE:** Operator Console Human-in-the-Loop (HITL) Workflow Intervention and Manual Override State Machine  
**STATUS:** PROPOSED (C03 Solution Design Complete)  

---

## 1. Problem Statement
Operator Console lacks formal state machine hooks to pause in-flight workflows, inspect intermediate generation artifacts, override prompts, and force manual take approvals.

---

## 2. Current Specification Baseline (v0.9.0)
The v0.9.0 specification lacks formal schema definitions, explicit state boundaries, and robust error/concurrency semantics for this domain.

---

## 3. Proposed Specification Changes (Option A vs Option B)

### OPTION_A: Strongest Practical Solution (Recommended)
First-class HITL workflow states in R06 with authenticated WebSocket command channel to R13 Operator Console.

**Exact Architectural Changes:**
Integrate formal HITL review states into WorkflowRun and GenerationJob state machines: WAITING_HUMAN_APPROVAL, OVERRIDDEN_BY_OPERATOR, REGENERATION_REQUESTED, ABORTED_BY_OPERATOR. Real-time WebSocket event bridge in R13. Complete operator audit log tracking user ID, timestamp, and modification reason.

### OPTION_B: Credible Alternative / Trade-off Analysis
Direct database manipulation by administrators without workflow engine awareness.

---

- **INVARIANTS_AFFECTED:** INV-002, INV-007
