# Superpowers Capability Mapping

Use Superpowers mainly as an engineering-process layer.

Suggested mappings:
- Council solution design -> brainstorming / writing-plans
- Build packet planning -> writing-plans
- Implementation -> test-driven-development
- Debugging failures -> systematic-debugging
- Per-task review -> requesting-code-review / receiving-code-review
- Final repo gate -> verification-before-completion
- Parallel independent tasks -> dispatching-parallel-agents
- Isolated branches -> using-git-worktrees
- Finish/release -> finishing-a-development-branch

Do not expect Superpowers alone to create genuinely different architecture lenses.
Role diversity still comes from the Council role charters and context isolation.
